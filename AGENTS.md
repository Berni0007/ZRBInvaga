# ZRBinvaga — режим Invasion для Arma Reforger

Этот файл — рабочая инструкция для ИИ-помощника (Codex и др.) и одновременно сводка состояния проекта.
Codex читает `AGENTS.md` из корня репозитория автоматически. Перед любой задачей прочитай его целиком.

Последнее обновление: 19.11.2026, коммит `256e45f`.

## 1. Что это за проект

Игровой режим **Invasion** по образцу Squad для модового сервера Arma Reforger (сообщество ZARUBA, 128 игроков).

- Атака берёт точки **строго по порядку**. Взятую точку отбить нельзя.
- У каждой стороны свои **тикеты**, есть **таймер** матча.
- После матча карта меняется, ротация своя (ещё не сделана).
- Фракции модовые (РФ / НАТО, возможно UA). Сейчас в тестах стоят штатные US / USSR.
- **Ранение и поднятие штатные**, их не трогаем.
- **FOB игроки не строят.** Вместо FOB: хабы на точках, rally отрядов, мобильный хаб атаки.

Дизайн-документ: https://claude.ai/artifact/14bZN9sCMWyX1hpM6NXDwN
Макет HUD: https://claude.ai/artifact/HAt7jU2kTP5WFfCzTcvAqQ (выбран вариант A «Линия фронта»).

### Решения владельца (Berni) — не менять без согласования

| Тема | Решение |
| --- | --- |
| Захват | Прогресс тянет та сторона, которой больше в зоне, в обе стороны. Пустая точка или равенство — прогресс замирает. |
| HUD захвата | Атака видит только полосу прогресса, и только стоя в зоне. Оборона видит лишь плашку «Точку N захватывают», без процентов. Численность на точке не показывается никому. |
| HUD тикетов | На экране — **только тикеты своей стороны** (плашка НАТО/РФ справа сверху). Тикеты противника не показываются. Плашка выбирается **по фракции**, не по роли. |
| Таймер и цепочка точек | **Только на полноэкранной карте.** На экран не выводятся, в том числе в конце матча. |
| Rally | Рация отряда. Ставит **командир + ещё 1 боец его отряда рядом**. Спавн только для своего отряда. **9 спавнов, потом рация исчезает.** **Враг ближе 50 м к развёрнутому rally — рация исчезает.** Новую рацию командир берёт **только на мейне** (ящик «Взять рацию rally»), одна рация на отряд. Рация по фракции: НАТО — AN/PRC-77, РФ — Р-107М. |
| Хаб на точке | Стоит на каждой точке заранее, на нём спавнится оборона. Ресурсов на старте нет — их привозят с мейна. После захвата хаб **переходит к атаке**: спавн только для захватившей стороны, ресурсы остаются. |
| Станции | Станции пополнения ставятся на точках. Ремонтная станция — под вопросом. |
| Техника | Спавнится **только на мейне**. |
| КШМ (мобильный хаб) | Своя реализация на штатном командном грузовике (штатная КШМ Conflict вне Conflict не работает). Действия «Развернуть/Свернуть КШМ» у кузова, спавн для всей фракции, враг в 50 м выключает спавн, максимум 2 на сторону. **Ресурсы в КШМ для пополнения, пополняются на мейне.** Остальное штатно. |
| Мобильный хаб атаки (старое) | Два вида: техника и разворачиваемый объект. Спавнятся все игроки стороны. Ограничено **число хабов** (не спавнов). Спавн выключается, если враг ближе 50 м. Появляется на мейне **без ресурсов**, пополняют игроки или подъехавший грузовик снабжения. |
| Старт обороны | Оборона на старте спавнится на мейне или на точке 1. |
| Киты, звания | Пока без ограничений. |

## 3. Что сделано (по этапам)

### Этап 1 — ядро ✅
- Цепочка точек по `Order`, только текущая точка активна, взятая блокируется навсегда.
- Тикеты: атака 300, оборона 800, −1 за респаун, первый спавн бесплатный, +100 атаке за точку. На последней точке тикеты обороны обнуляются.
- Таймер: подготовка 180 с → штурм 3600 с, +600 с за точку. Время вышло → победа обороны.
- Конец матча через `SCR_GameModeEndData.CreateSimple` + `EndGameMode`.
- **Проверено в игре:** цепочка 1→2→3, тикеты 300→400→500, обнуление обороны, экран VICTORY, списание тикета за смерть.

### Этап 2 — инструменты расстановки в редакторе ✅
- У точки в World Editor видны сфера радиуса, подпись `#N name [60s, min 2]` (латиница — кириллицу отладочный шрифт не рисует) и стрелка к следующей точке.
- Оранжевый цвет — порядок, красный — ошибка (`duplicate #N`, `missing #N`, `order < 1`). Те же ошибки пишутся в лог при старте.

### Захват как в Squad ✅
- Свой подсчёт людей: `ZW_InvasionPoint.ZW_CountInside` через `QueryEntitiesBySphere` по атрибуту `m_fCaptureRadius` (по умолчанию 40 м). Считаются живые `ChimeraCharacter` нужной фракции.
- Перетягивание в обе стороны, пустая точка или равенство — замирает, `m_iMinAttackers` для старта захвата.
- Реплицируются `m_iProgress` и `m_bBeingCaptured`.

### Этап 3 — HUD ✅ частично
- На экране: плашка тикетов **своей** стороны справа сверху (текстуры `UI/Textures/ZW_Tickets_NATO_UI.edds`, `ZW_Tickets_RF_UI.edds`). Плашка выбирается по ключу фракции: атрибут «Ключи фракций РФ» (по умолчанию `USSR,RF,RU,RUS`), остальные — НАТО.
- На полноэкранной карте: цепочка точек (ромбы; взятые синие, текущая оранжевая, у атаки дальние — «?», у обороны красные) и таймер штурма. HUD на карте не перехватывает курсор.
- Экран подготовки с обратным отсчётом и подсказкой по стороне (вне карты).
- Виджет захвата у атаки (только в зоне): сверху по центру, «Захват / Точка оспаривается / Точку отбивают» и полоса. **Проверено** в старой версии; новая раскладка ещё не проверена в игре.
- Плашка обороны «Точку N захватывают». **Не проверено** — нужен второй игрок.
- Позиции и цвета задаются из скрипта (`ApplyLayout`, `ApplyColors`), потому что `Offset*` и фоны из `.layout` работали неправильно.

### Этап 4 — Rally ✅ основа работает
- Rally = **штатная разворачиваемая рация** (`Radio_Deployable_Base.et` и наследники, например `Radio_ANPRC77.et`) через `modded class SCR_RestrictedDeployableSpawnPointComponent`. Все изменения включаются **только если в гейм-моде есть `ZW_RallyManagerComponent`**, в других режимах рация штатная.
- Отключены ограничения Conflict: `m_bRestrictDeploy`, базы, радиопокрытие. Свои правила в `ZW_RallyManagerComponent.CanDeployRally`: командир, второй боец в 15 м, отряд «заряжен», нет врага в 50 м, не ближе 100 м к обычной спавн-точке.
- Спавн только для своего отряда, один rally на отряд, враг в 50 м блокирует спавн (штатный запрос персонажей, радиус из менеджера).
- Бюджет rally — `SPAWNTICKET`; лимит 9 спавнов считает `ZW_RallyManagerComponent` в `OnPlayerSpawnFinalize_S`. На 9-м спавне — `Dismantle()`, отряд попадает в `m_aDepletedGroups` (реплицируется).
- Игрок без отряда при спавне попадает в первый неполный отряд своей фракции (или в новый) через `SCR_PlayerControllerGroupComponent.RequestJoinGroup`.
- Экран возрождения с картой (`SCR_MenuSpawnLogic`): выбор фракции, снаряжения и точки. Rally подписан «Rally — отряд N».
- **Проверено в игре:** рация разворачивается действием F, спавн на rally работает (лог `Rally отряда 1000: спавн 1/9`, тикеты 300→299). Лимит работает: на последнем спавне rally сворачивается (через 0,5 с после спавна — иначе падал штатный обработчик), повторное развёртывание даёт отказ «Rally израсходован — пополните у хаба». Тикеты списываются при каждом возрождении (300→299→298).

### Этап 7 — КШМ ✅ основа работает (США и РФ)
- `ZW_KSHM_US.et` на `M923A1_command`: переопределён `ActionsManagerComponent` (GUID `{C97BE5489221AE18}`), добавлен контекст `zw_kshm` у кузова — штатные действия грузовика сохранились.
- **Проверено в игре:** развернуть/свернуть, точка «КШМ» на экране возрождения, спавн на ней.
- `ZW_KSHM_RF.et` на `Ural4320_command` — тот же GUID `ActionsManagerComponent`, контекст у кузова `0 1.4 -3.5`. Проверено в игре.
- **Ресурсы ✅ (проверено в игре):** в КШМ штатный `SCR_ResourceComponent` (CARGO_VEHICLE, 1000, старт 0) + штатные действия «Загрузить/Выгрузить снабжение» у кузова. На мейне `ZW_MainSupply` (STORED). При развёртывании спавнится `ZW_KshmArsenal_*` (наследник `ArsenalBox_US/USSR`, потребитель переопределён на CARGO_VEHICLE, радиус 15 м). Снабжение включается в `ZW_RallyManagerComponent.OnGameModeStart` (`SetResourceTypeEnabled`).
- Осталось: появление только на мейне, проверка врага в 50 м вдвоём.

## 4. Грабли, на которые уже наступили (не повторять)

1. **`SCR_CaptureAndHoldArea.GetSphereRadius()` в рантайме возвращает 1.** Для зоны используй `ZW_InvasionPoint.GetCaptureRadius()`.
2. **Штатная смена владельца Capture & Hold не срабатывала** — захват полностью свой (`ZW_Tick`).
3. **Статические переменные в Workbench переживают перезапуск Play**, а точки из редактора тоже регистрируются. Список точек фильтруется по `GetOwner().GetWorld()` (`PrunePoints`).
4. **Штатная рация вне Conflict не разворачивается** без трёх вещей: `SCR_PlayerSpawnPointManagerComponent` в гейм-моде + `EnableDeployableSpawnPoints(true)`; `m_bRestrictDeploy = false` и отключённые проверки баз/радиопокрытия; отряд, который знает **контроллер игрока**.
5. **`SCR_GroupsManagerComponent.AddPlayerToGroup` не обновляет компонент группы у контроллера** → штатный `Deploy` видит отряд −1 и молча отказывает. Вступать через `SCR_PlayerControllerGroupComponent.RequestJoinGroup`; разворачивать через `DeployByGroup`.
6. **Бюджет `SUPPLIES` ломает спавн на rally** — система снабжения в Invasion не настроена. Rally работает на `SPAWNTICKET`.
7. **Прямой вызов `Deploy()` из скрипта и действие игрока вели себя по-разному.** Проверять только через действие игрока.
8. **Нельзя сменить класс унаследованного объекта** (например, `m_SpawnLogic`) ни в мире, ни в «Change Class». Способ: в Prefab edit mode поменять любое поле компонента, сохранить — Workbench запишет компонент с его GUID в `.et`, — затем отредактировать текст.
9. **Кириллица в `DebugTextWorldSpace` превращается в кракозябры** — подписи в редакторе только латиницей. Шрифт HUD (`NotoSans-Enhanced-Regular-JP-KOR-SC-LAT.fnt`) кириллицу рисует.
10. **`Offset*` в `.layout` давали нулевые и сдвинутые виджеты, фоны не рисовались.** Размеры, позиции и цвета HUD — из скрипта (`FrameSlot`, `SetColor`).
11. **Workbench сам выбирает фракцию** при Play в автоспавне. С экраном возрождения выбирай фракцию вручную.
12. **Рация чужой фракции не разворачивается** (действия Deploy нет) — это правильно. Каждой стороне нужна своя рация.
13. **Таймер подготовки идёт, пока игрок в меню возрождения** — для сервера это проблема (см. этап 11).
14. **Экран выбора фракции и возрождения — тоже полноэкранная карта.** HUD, встроенный в её корень, ломает мышь в меню. HUD встраивается в карту, только когда персонаж **жив** (после смерти труп ещё считается управляемым).
15. **`Dismantle()` внутри `OnPlayerSpawnFinalize_S` роняет штатный обработчик спавна** — сворачивать через `CallLater`.
16. После отладочной смерти через 5 с после спавна (`m_bDebugKillAfterRallySpawn`) мышь в меню возрождения может не реагировать; клавиатура (стрелки, пробел) работает. При обычной смерти не замечено.

17. **Штатная КШМ (`SCR_CampaignMobileAssemblyComponent`) работает только в Conflict** — нужен командный модуль кампании. Делаем свою (`ZW_KshmComponent`).
18. Переопределить штатный компонент в префабе можно только с его GUID (узнать: временно изменить поле в мире и сохранить слой). Массивы `ActionContexts`/`additionalActions` при переопределении **сливаются** со штатными.

19. Готовые .et штатных префабов (для GUID компонентов и конфигов снабжения) удобно смотреть в публичных модах на GitHub (`gh search code ... --extension et`), например CoalitionArma/Coalition-Reforger-Framework. GUID штатных компонентов в переопределениях модов совпадают с ванильными.

### Известные ошибки, ещё не исправленные
- `SCR_SupportStationManagerComponent.AddSupportStation`: пустой `m_aSupportStationPriority`. Развёрнутая рация пытается зарегистрироваться как станция снабжения, а менеджер станций в режиме не настроен. Спавн не ломает, но засоряет лог VM-исключениями.

### Этап 5. Хаб на точке

## 6. Промпт для Codex

> Ты — помощник по разработке игрового режима Invasion для Arma Reforger (движок Enfusion, язык **Enforce Script**). Репозиторий — аддон Workbench `ZRBinvaga`. Владелец — Berni, общается по-русски, работает итеративно: сначала короткий план и что поменяется, потом код. Отвечай кратко.

> **Перед работой**
> 1. Прочитай этот `AGENTS.md` целиком, особенно раздел «Грабли».
> 2. Прочитай файлы, которые собираешься менять, и связанные с ними.
> 3. Если задача меняет игровые правила из таблицы «Решения владельца» — не меняй, а задай вопрос.

> **Язык и API**
> - Это **не C# и не C++**. Enforce Script: `class X : Y`, `override`, `modded class`, `ref` для владения объектами, `array<T>`, `map<K,V>`, `set<T>`, `string.Format("%1", a)`, `Print(msg, LogLevel.NORMAL)`, `GetGame().GetCallqueue().CallLater(fn, ms, repeat, args...)`.
> - **Любой метод штатного класса проверяй** по справочнику API: https://community.bistudio.com/wikidata/external-data/arma-reforger/ArmaReforgerScriptAPIPublic/ (страницы вида `interfaceSCR__ИмяКласса-members.html`). Не выдумывай методы. Если метода нет в справочнике — скажи об этом и предложи способ проверить в Workbench.
> - Исходников игры в репозитории нет. Если поведение штатного кода неясно — добавь диагностический `Print` и попроси владельца прогнать тест, а не гадай.
>
> **Правила кода**
> - Префикс всех своих классов, файлов и префабов: `ZW_`. Логи начинаются с `[ZW_Invasion]`, отладочные — `[ZW_Invasion][DBG]` и уровень `LogLevel.WARNING`.
> - Стиль: Allman (фигурные скобки на новой строке), табы, разделитель `//------------------------------------------------------------------------------------------------` перед каждым методом, комментарии и тексты для игроков — по-русски.
> - **Сервер решает, клиент показывает.** Состояние меняется только на сервере (`Replication.IsServer()`), для клиентов — поля `[RplProp()]` + `Replication.BumpMe()` после изменения.
> - **Не правь штатные префабы и файлы игры.** Меняй поведение через `modded class`, и только при условии, что режим Invasion активен (`ZW_RallyManagerComponent.GetInstance()` или аналогичный компонент гейм-мода). В других режимах всё должно работать штатно.
> - Настраиваемые значения — атрибутами `[Attribute(...)]` с русским описанием и категорией (`Invasion`, `Rally`, `Invasion Debug`), а не константами.
> - Отладочные возможности — только флагами в категории `Invasion Debug`, по умолчанию выключены.
> - Не добавляй тяжёлых операций в каждый кадр: сервер на 128 игроков.
>
> **Файлы Workbench (`.et`, `.layer`, `.layout`, `.meta`)**
> - Это текст, их можно править, но аккуратно: сохраняй отступы в один пробел и формат `Класс "{GUID}" { ... }`.
> - Новый компонент в префабе получает новый уникальный 16-символьный hex-ID в фигурных скобках.
> - Переопределить **штатный** компонент в своём префабе можно только с его оригинальным ID. Если ID неизвестен — попроси владельца: открыть префаб в Prefab edit mode, поменять любое поле компонента, сохранить и прислать файл.
